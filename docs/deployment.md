```bash

Configuration

Before deploying, update infra/parameters.json:

Replace all <placeholder> values with your actual resource names.
Set publisherEmail to your real email address.
Set tenantId to your Azure AD tenant ID.
Set apiAppIdUri using the App Registration steps below.
Create App Registration

The App Registration is required for APIM JWT validation.

# Create app registration for the Search API
az ad app create \
  --display-name "nlp-pipeline-search-api" \
  --sign-in-audience AzureADMyOrg

# Get the application ID
APP_ID=$(az ad app list \
  --display-name "nlp-pipeline-search-api" \
  --query "[0].appId" -o tsv)

# Configure the App ID URI
az ad app update \
  --id $APP_ID \
  --identifier-uris "api://$APP_ID"

echo "apiAppIdUri: api://$APP_ID"
echo "tenantId: $(az account show --query tenantId -o tsv)"
Deployment Order

The resources should be deployed in the following order because later steps depend on outputs generated by earlier steps.

Step 1: Deploy Core Infrastructure

Run the main Bicep deployment:

az deployment group create \
  --resource-group nlp-pipeline-rg \
  --template-file infra/main.bicep \
  --parameters @infra/parameters.json \
  --parameters \
    newsApiKey="<your-newsapi-key>" \
    languageApiKey="<your-language-key>" \
    openAiApiKey="<your-openai-key>" \
    searchApiKey="<your-search-admin-key>" \
    hashFunctionKey="placeholder" \
    searchApiFunctionKey="placeholder" \
    nlpTriggerFunctionKey="placeholder" \
    auditLoggerFunctionKey="placeholder" \
    publisherEmail="<your-email>" \
    tenantId="<your-tenant-id>" \
    apiAppIdUri="api://<your-app-id>"

Function keys are initially set to "placeholder" because the actual keys are generated after the Function App is deployed. They are replaced in Step 4.

Step 2: Deploy Function App Code
cd functions

func azure functionapp publish <functionAppName> --node

cd ..
Step 3: Retrieve Function Keys
# Function App and resource group
FUNCTION_APP="<your-function-app-name>"
RG="nlp-pipeline-rg"

# Get the fn-hash-url key
HASH_KEY=$(az functionapp function keys list \
  --name $FUNCTION_APP -g $RG \
  --function-name fn-hash-url \
  --query "default" -o tsv)

# Get the fn-search-api key
SEARCH_KEY=$(az functionapp function keys list \
  --name $FUNCTION_APP -g $RG \
  --function-name fn-search-api \
  --query "default" -o tsv)

# Get the fn-nlp-trigger key
NLP_TRIGGER_KEY=$(az functionapp function keys list \
  --name $FUNCTION_APP -g $RG \
  --function-name fn-nlp-trigger \
  --query "default" -o tsv)

# Get the fn-audit-logger key
AUDIT_KEY=$(az functionapp function keys list \
  --name $FUNCTION_APP -g $RG \
  --function-name fn-audit-logger \
  --query "default" -o tsv)

echo "Hash key:         $HASH_KEY"
echo "Search API key:   $SEARCH_KEY"
echo "NLP trigger key:  $NLP_TRIGGER_KEY"
echo "Audit logger key: $AUDIT_KEY"
Step 4: Re-deploy with Real Function Keys

Run the Bicep deployment again with the actual function keys:

az deployment group create \
  --resource-group nlp-pipeline-rg \
  --template-file infra/main.bicep \
  --parameters @infra/parameters.json \
  --parameters \
    newsApiKey="<newsapi-key>" \
    languageApiKey="<language-key>" \
    openAiApiKey="<openai-key>" \
    searchApiKey="<search-admin-key>" \
    hashFunctionKey="$HASH_KEY" \
    searchApiFunctionKey="$SEARCH_KEY" \
    nlpTriggerFunctionKey="$NLP_TRIGGER_KEY" \
    auditLoggerFunctionKey="$AUDIT_KEY" \
    publisherEmail="<your-email>" \
    tenantId="<tenant-id>" \
    apiAppIdUri="api://<app-id>"

Key Vault Integration (Production)

For production deployments, secrets should be stored in Azure Key Vault rather than passed as plaintext values.

Create Key Vault
az keyvault create \
  --name nlp-pipeline-kv \
  -g nlp-pipeline-rg \
  --location eastus
Store Secrets
az keyvault secret set \
  --vault-name nlp-pipeline-kv \
  --name newsapi-key \
  --value "<key>"

az keyvault secret set \
  --vault-name nlp-pipeline-kv \
  --name language-api-key \
  --value "<key>"

az keyvault secret set \
  --vault-name nlp-pipeline-kv \
  --name openai-api-key \
  --value "<key>"

az keyvault secret set \
  --vault-name nlp-pipeline-kv \
  --name search-api-key \
  --value "<key>"
Grant the Function App Access to Key Vault
FUNCTION_PRINCIPAL=$(az functionapp identity show \
  --name <function-app-name> \
  -g nlp-pipeline-rg \
  --query principalId -o tsv)

az keyvault set-policy \
  --name nlp-pipeline-kv \
  --object-id $FUNCTION_PRINCIPAL \
  --secret-permissions get list
Reference Key Vault Secrets from Function App Settings
az functionapp config appsettings set \
  --name <function-app-name> \
  -g nlp-pipeline-rg \
  --settings \
  "NEWSAPI_KEY=@Microsoft.KeyVault(VaultName=nlp-pipeline-kv;SecretName=newsapi-key)" \
  "LANGUAGE_API_KEY=@Microsoft.KeyVault(VaultName=nlp-pipeline-kv;SecretName=language-api-key)"
Zero-Downtime Index Updates

For breaking Search index changes such as changing field types, removing fields, or changing analyzers, create a new versioned index instead of modifying the active index.

# 1. Create the new version
SEARCH_INDEX_NAME="articles-v2" node scripts/create-index.js

# 2. Backfill the new index
curl -X POST https://<fn-app>.azurewebsites.net/api/fn-index-refresh \
  -d '{"date": "2024-01-15", "category": "technology"}'

# Repeat the backfill for all required dates and categories

# 3. Swap the alias to the new index
node scripts/create-search-alias.js \
  --alias articles \
  --target articles-v2

# 4. Clients using the "articles" alias now use articles-v2

# 5. Remove the old index after verification
az search index delete \
  --service-name <search> \
  -g nlp-pipeline-rg \
  --index-name articles-v1 \
  --yes
Monitoring Setup
Application Insights Alerts

Create an alert for the fn-enrich error rate:

az monitor metrics alert create \
  --name "fn-enrich-error-rate" \
  -g nlp-pipeline-rg \
  --scopes "<app-insights-resource-id>" \
  --condition "count exceptions/count > 50" \
  --window-size 5m \
  --evaluation-frequency 1m \
  --action "<action-group-id>"
ADF Pipeline Failure Alert

Configure the ADF pipeline failure alert from the Azure portal:

Azure portal → Data Factory → Monitor → Alerts → New alert rule

Use the following settings:

Metric: PipelineFailedRuns
Condition: Count > 0
Action: Email notification
Queue Depth Alert

Create an alert for the enrichment queue:

az monitor metrics alert create \
  --name "enrich-queue-depth" \
  -g nlp-pipeline-rg \
  --scopes "<storage-account-resource-id>" \
  --condition "avg ApproximateMessageCount > 500" \
  --window-size 15m \
  --evaluation-frequency 5m
